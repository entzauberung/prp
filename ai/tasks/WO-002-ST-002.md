# WO-002-ST-002 Provider schema 出站前严格拒绝测试

## 子任务目标

证明 OpenAI-compatible Provider 对含非标准数字的 schema 在任何 HTTP 请求发出前拒绝。

## 执行顺序

1. 阅读 Provider `_build_payload`、`complete` 和 structured output 现有测试。
2. 增加参数化非法 schema 测试，使用现有 respx mock。
3. 断言调用被拒绝且 mock route 调用数为零。
4. 保留合法 structured output payload 断言。
5. 运行目标 pytest 和 ruff；仅在直接缺陷时修复 Provider。

## 前置条件

- WO-002-ST-001 完成。

## 输入

- `src/prp_runtime/providers/openai_compatible.py`
- `tests/unit/providers/test_openai_compatible.py`

## 输出

- Provider strict schema 的行为级和零出站副作用证据。

## 依赖

- WO-002-ST-001。

## 改动坐标

- `_build_payload` strict schema 分支（仅失败时）。
- structured output 测试区。

## 允许文件

- `src/prp_runtime/providers/openai_compatible.py`
- `tests/unit/providers/test_openai_compatible.py`
- `ai/STATE.md`
- `ai/LATEST-REPORT.md`

## 禁止文件

- Provider base、其他源码/测试、依赖、配置、Git metadata、README、CONTROL、执行协议。

## 精确实施要求

- 覆盖 `NaN`、`Infinity`、`-Infinity`、`1e999` 的 schema 文本。
- 使用支持 structured output 的 profile，避免因能力检查提前失败。
- 只要求 strict ValueError 类拒绝和零 HTTP 调用，不新增公开异常类型。
- 禁止真实网络；所有请求必须由 respx 捕获。

## 完成定义

- 四类非法 schema 均在出站前拒绝，合法 schema payload 行为不变。

## 验收标准

- route 调用数为零；无 skip/xfail；无 API/请求形状变化。

## 允许执行命令

- `uv run pytest tests/unit/providers/test_openai_compatible.py -q`
- `uv run ruff check src/prp_runtime/providers/openai_compatible.py tests/unit/providers/test_openai_compatible.py`

## 禁止执行命令

- 全量 pytest/ruff/mypy、真实网络、服务、安装、构建、Git 写操作

## 验证等级

- R1

## 最大修复轮数

- 2

## 最大运行时间

- 每条命令 180 秒。

## CPU 和内存风险

- 低；mock HTTP 单模块，无后台进程、Node 或 Cargo。

## 失败处理方式

- 只修 Provider strict payload 直接路径；同一失败两次即 BLOCKED。

## HARD STOP 条件

- 测试触发真实网络，或需要修改 ProviderRequest、API、错误合同、依赖或其他模块。
