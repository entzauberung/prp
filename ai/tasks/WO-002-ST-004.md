# WO-002-ST-004 三边界联合定向回归

## 子任务目标

联合验证 Settings、Provider、SQLite、conformance 和目标静态类型，确认三个独立修复没有跨模块回归。

## 执行顺序

1. 核对前三个 ST 的报告和修改文件。
2. 串行运行联合定向 pytest。
3. 运行目标 ruff。
4. 运行三个生产模块的目标 mypy。
5. 若失败，只在六个允许文件内做一次直接修复并重跑同一失败命令。

## 前置条件

- WO-002-ST-001、WO-002-ST-002、WO-002-ST-003 全部完成。

## 输入

- 三个边界模块、三份测试和 conformance 测试。

## 输出

- 联合 R1 回归和静态检查结果。

## 依赖

- WO-002-ST-003。

## 改动坐标

- 仅前三个 ST 的六个文件中被联合测试证明的直接缺陷。

## 允许文件

- `src/prp_runtime/settings.py`
- `src/prp_runtime/providers/openai_compatible.py`
- `src/prp_runtime/storage/sqlite.py`
- `tests/unit/providers/test_base.py`
- `tests/unit/providers/test_openai_compatible.py`
- `tests/unit/storage/test_store.py`
- `ai/STATE.md`
- `ai/LATEST-REPORT.md`

## 禁止文件

- 其他源码/测试、conformance 测试修改、依赖、配置、schema、Git metadata、CONTROL、执行协议。

## 精确实施要求

- 命令一次一条；不删除、skip 或放宽失败测试。
- conformance 文件只运行不修改。
- mypy 仅目标生产文件，不扩大到全项目。
- 报告逐条记录命令、结果和实际修改文件。

## 完成定义

- 联合 pytest、目标 ruff、目标 mypy 全部通过。

## 验收标准

- 三个真实边界测试均执行；无网络、无真实数据库、无范围外修复。

## 允许执行命令

- `uv run pytest tests/unit/providers/test_base.py tests/unit/providers/test_openai_compatible.py tests/unit/storage/test_store.py tests/conformance/test_repair.py -q`
- `uv run ruff check src/prp_runtime/settings.py src/prp_runtime/providers/openai_compatible.py src/prp_runtime/storage/sqlite.py tests/unit/providers/test_base.py tests/unit/providers/test_openai_compatible.py tests/unit/storage/test_store.py tests/conformance/test_repair.py`
- `uv run mypy src/prp_runtime/settings.py src/prp_runtime/providers/openai_compatible.py src/prp_runtime/storage/sqlite.py`

## 禁止执行命令

- 全量 pytest/ruff/mypy、网络、服务、安装、构建、Git 写操作

## 验证等级

- R1

## 最大修复轮数

- 1

## 最大运行时间

- 每条命令 300 秒。

## CPU 和内存风险

- 中低；定向 Python 测试和静态检查，串行，无后台进程、Node 或 Cargo。

## 失败处理方式

- 只修失败命令直接暴露的六文件问题；再次失败即 BLOCKED。

## HARD STOP 条件

- 需要修改 conformance、其他模块、依赖或配置；出现第二次同一失败或资源异常。
