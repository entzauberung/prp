# WO-003-ST-002 最终工作树人工 R2 门禁

## 子任务目标

在本蓝图下获得新的用户明确批准后，对 ST-001 已冻结的最终工作树执行全量质量门禁和最终 Git 双视图检查。

## 执行顺序

1. 未取得本蓝图下明确批准时停止，状态标记 BLOCKED/待批准，不运行命令。
2. 批准后先记录门禁输入的 Git 三视图。
3. 串行运行全量 pytest、ruff、mypy。
4. 执行 staged 与 unstaged whitespace check。
5. 再次读取 Git 三视图，确认测试未产生未忽略产物或源码变化。
6. 覆盖最终报告，分别列 staged、unstaged、untracked 和全部命令结果。
7. 仅全部通过时将 STATE 标记 COMPLETED；说明随后 STATE/REPORT 写入是预期控制面差异。

## 前置条件

- WO-003-ST-001 通过且范围冻结。
- 用户明确批准执行本 ST 的 R2；旧蓝图批准无效。

## 输入

- ST-001 最终文件表和当前完整工作树。

## 输出

- 同一工作树的全量门禁、前后 Git 三视图和最终完成状态。

## 依赖

- WO-003-ST-001。

## 改动坐标

- 仅协议要求的 `ai/STATE.md`、`ai/LATEST-REPORT.md`。

## 允许文件

- `ai/STATE.md`
- `ai/LATEST-REPORT.md`

## 禁止文件

- 全部源码、测试、依赖、配置、其他文档、Git metadata、CONTROL 和执行协议。

## 精确实施要求

- 命令一次一条，顺序不可跳过；失败后不得现场修复或继续后续门禁。
- 全量测试验证工作树，不把 staged index 冒充唯一输入；报告保留两种视图。
- 测试前后除 ignored cache 外不得出现新文件或源码差异。
- 最终不得执行 git add/commit/branch/tag/push；提交决策不属于本蓝图。

## 完成定义

- pytest 0 failure、ruff 0 error、mypy 0 error、双 Diff check 通过，前后文件集合一致。

## 验收标准

- 报告含每条命令原始结论和前后逐文件 Git 三视图。
- 无真实网络、无服务、无构建产物、无门禁后源码/测试变更。

## 允许执行命令

- `git status --short`
- `git diff --cached --name-status`
- `git diff --name-status`
- `git ls-files --others --exclude-standard`
- `uv run pytest -q`
- `uv run ruff check src tests`
- `uv run mypy src/prp_runtime`
- `git diff --cached --check`
- `git diff --check`

## 禁止执行命令

- 未获批准的任何命令
- Git 写操作、依赖安装、网络、服务、构建、发布、数据库迁移、并行命令

## 验证等级

- R2（人工批准门禁）

## 最大修复轮数

- 0；任一失败立即 BLOCKED。

## 最大运行时间

- 每条命令 600 秒。

## CPU 和内存风险

- 中；全量 Python 测试和静态检查，必须串行。无 Node/Cargo，无网络和后台进程。

## 失败处理方式

- 记录失败命令、输出摘要、已执行/未执行项和当前文件视图，标记 BLOCKED 等待人工决策。

## HARD STOP 条件

- 未获明确批准；任一命令失败/超时；前后文件集合变化；OOM、严重卡顿、进程被杀或磁盘不足。
