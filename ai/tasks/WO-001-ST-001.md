# WO-001-ST-001 Git staged/unstaged/untracked 基线采集

## 子任务目标

用只读 Git 命令采集三个独立视图和 numstat，替换旧报告中无法核对的 78/81 数字。

## 执行顺序

1. 读取 CONTROL、STATE 和当前 ST，确认未沿用旧状态。
2. 依次读取工作区总状态、staged 文件、unstaged 文件和 untracked 文件。
3. 分别读取 staged/unstaged numstat。
4. 分别执行 index 和工作树 whitespace 检查。
5. 将实际逐文件输出写入 LATEST-REPORT，不使用“另附”或 mtime。
6. 更新 STATE 指向 WO-001-ST-002。

## 前置条件

- 当前仓库可读取 Git 状态。
- `ai/EXECUTION-PROTOCOL.md` 存在且未修改。

## 输入

- 当前 Git index、working tree、untracked 集合。
- `ai/CONTROL.md` 的范围和禁止项。

## 输出

- staged、unstaged、untracked 三张逐文件表。
- staged、unstaged 两张 numstat 表和双 whitespace 结果。

## 依赖

- 无。

## 改动坐标

- 仅执行状态与最新报告。

## 允许文件

- `ai/STATE.md`
- `ai/LATEST-REPORT.md`

## 禁止文件

- 全部源码、测试、依赖、配置、文档、Git metadata、`ai/CONTROL.md`、`ai/EXECUTION-PROTOCOL.md`。

## 精确实施要求

- 三个视图分别编号、分别计数；同一文件出现在 staged 和 unstaged 时必须在两表都出现。
- 报告必须逐行写入 name-status 和 numstat 输出，不得只写汇总数字。
- ignored 文件不计为 untracked；若发现疑似构建产物，记录路径并 BLOCKED。
- 不执行任何 Git 写操作，不尝试把三视图整理成单一 staged 集合。

## 完成定义

- 当前 Git 状态可由报告中的文件行独立复算，双 Diff check 通过。

## 验收标准

- 78/81 不再作为输入事实；报告产生当前实际数字。
- 无 mtime 归因、无“已附但未写入”的证据缺口。

## 允许执行命令

- `git status --short`
- `git diff --cached --name-status`
- `git diff --name-status`
- `git ls-files --others --exclude-standard`
- `git diff --cached --numstat`
- `git diff --numstat`
- `git diff --cached --check`
- `git diff --check`

## 禁止执行命令

- `git add`、`git restore`、`git reset`、`git commit`、`git branch`、`git tag`、`git push`
- 测试、ruff、mypy、构建、服务、网络、安装命令

## 验证等级

- R1（只读 Git 定向审计）

## 最大修复轮数

- 0；本任务不修项目文件。

## 最大运行时间

- 每条命令 120 秒。

## CPU 和内存风险

- 低；纯 Git 元数据和文本 Diff 统计。无需 CARGO_BUILD_JOBS，无 Node 内存设置，无网络和后台进程。

## 失败处理方式

- 任一命令失败或输出不一致时标记 BLOCKED，保留已取得证据，不换用写操作。

## HARD STOP 条件

- Git 状态不可读、任一 Diff check 失败、发现构建产物或需要 Git 写操作才能继续。
