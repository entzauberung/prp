# WO-003-ST-001 最终 Git 三视图与定向交付审计

## 子任务目标

重采最终 staged/unstaged/untracked，和 WO-001 基线逐文件比较，并用定向测试证明最终交付可进入人工 R2。

## 执行顺序

1. 读取 WO-001 基线和 WO-002 完成报告。
2. 重采三视图、两类 numstat 和双 whitespace check。
3. 对比基线，只允许六个边界文件和协议控制面发生预期变化。
4. 读取六个目标文件的实际工作树 Diff。
5. 串行运行交付定向 pytest 和 ruff。
6. 将实际 name-status、numstat、变化对照表和命令结果完整写入报告。
7. 全部通过后将状态推进到 WO-003-ST-002 待人工批准。

## 前置条件

- WO-002 完成。

## 输入

- WO-001 基线、当前 Git 三视图、WO-002 六个允许文件。

## 输出

- 最终可复算文件表、基线差异表、目标 Diff 审计和 R1 结果。

## 依赖

- WO-002。

## 改动坐标

- 仅执行状态与最新报告。

## 允许文件

- `ai/STATE.md`
- `ai/LATEST-REPORT.md`

## 禁止文件

- 全部源码、测试、依赖、配置、文档、Git metadata、CONTROL 和执行协议。

## 精确实施要求

- staged、unstaged、untracked 分别报告；不得写单一“总共 N 个暂存”替代。
- 报告必须包含实际 name-status 和 numstat 文件行，以及基线新增/删除/变化对照。
- `git diff --` 目标文件仅用于读取，不得据此执行 Git 写操作。
- 任一非允许文件相对基线发生变化即 BLOCKED，不进入 R2。

## 完成定义

- 最终范围可独立复算，双 Diff check 和定向测试/ruff 通过，无第三类文件。

## 验收标准

- 目标 Diff 与 WO-002 报告一致；无构建产物、无 skip/xfail、无“附件缺失”。

## 允许执行命令

- `git status --short`
- `git diff --cached --name-status`
- `git diff --name-status`
- `git ls-files --others --exclude-standard`
- `git diff --cached --numstat`
- `git diff --numstat`
- `git diff --cached --check`
- `git diff --check`
- `git diff -- src/prp_runtime/settings.py src/prp_runtime/providers/openai_compatible.py src/prp_runtime/storage/sqlite.py tests/unit/providers/test_base.py tests/unit/providers/test_openai_compatible.py tests/unit/storage/test_store.py`
- `uv run pytest tests/unit/providers/test_base.py tests/unit/providers/test_openai_compatible.py tests/unit/storage/test_store.py tests/conformance/test_repair.py -q`
- `uv run ruff check src/prp_runtime/settings.py src/prp_runtime/providers/openai_compatible.py src/prp_runtime/storage/sqlite.py tests/unit/providers/test_base.py tests/unit/providers/test_openai_compatible.py tests/unit/storage/test_store.py tests/conformance/test_repair.py`

## 禁止执行命令

- 全量 pytest/ruff/mypy、Git 写操作、网络、服务、安装、构建、发布

## 验证等级

- R1

## 最大修复轮数

- 0；交付冻结，不现场修复。

## 最大运行时间

- 每条命令 300 秒。

## CPU 和内存风险

- 中低；只读 Git 和定向 Python 验证，串行，无后台进程、Node 或 Cargo。

## 失败处理方式

- 任一差异或命令失败立即 BLOCKED，报告精确路径/命令，不返回 WO-002 现场修改。

## HARD STOP 条件

- 基线不完整、出现未允许文件、Diff check/定向验证失败或 Git 证据无法写入报告。
