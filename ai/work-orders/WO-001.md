# WO-001 Git 三视图基线与范围冻结

## 工单目标

重新采集 staged、unstaged、untracked 三类真实 Git 状态，废止 78/81 混用和 mtime 归因，并把当前项目状态分类为可审计基线。

## 要解决的问题

旧报告没有实际写入所称文件表，且门禁报告的 78 与用户转述的 81 不一致。没有一致基线就无法判断后续测试改动是否越界。

## 前置依赖

- 无。

## 本工单分约束

- 只读 Git；不得 add、restore、reset 或改动项目文件。
- 三个视图分别记录，不合并为一个模糊总数。
- mtime 不作为范围或授权证据。

## 允许改动范围

- `ai/STATE.md`
- `ai/LATEST-REPORT.md`

## 禁止改动范围

- 全部源码、测试、依赖、配置、README、Git metadata 和执行协议。

## 改动坐标

- Git index、working tree、untracked/ignored 边界。
- 新蓝图允许总范围和当前项目文件分类。

## 子任务顺序

1. WO-001-ST-001：采集 staged/unstaged/untracked、numstat 与双 whitespace check。
2. WO-001-ST-002：按新 CONTROL 分类基线并冻结后续允许坐标。

## 完成定义

- 三视图逐文件可读，数字可由表格复算。
- 当前文件全部归类；无构建产物、无无法解释的第三类文件。
- 后续允许修改范围固定为 CONTROL 和 WO-002 明列文件。

## 验收标准

- 报告包含实际 `name-status` 和 `numstat` 文件行，不写“另附”。
- `git diff --cached --check` 与 `git diff --check` 均通过。
- 78/81 差异被事实替换，不通过猜测解释。

## 测试要求

- 不运行代码测试；仅执行 ST-001 列出的只读 Git 命令。

## 资源策略

- R1 只读命令串行，每条最多 120 秒，无网络、无后台进程。

## 风险

- 仓库低基线可能让 staged Diff 全部显示新增；必须如实记录，不用 mtime伪造历史。
- 新蓝图文件可能同时形成 staged 与 unstaged 差异，必须分别列出。

## 回滚点

- 本工单不改项目文件；仅覆盖 STATE/REPORT，可重新采集后覆盖。

## 硬停止条件

- Git 三视图不可读、命令输出互相矛盾、发现构建产物或需要 Git 写操作。
- 存在无法归类文件，或必须读取聊天历史才能解释当前状态。
