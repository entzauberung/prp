# WO-002 严格 JSON 三边界行为证据

## 工单目标

用实际公开/模块边界调用证明 Settings、Provider 和 SQLite 对非标准 JSON 的拒绝行为，而不是只扫描源码字符串或单独测试标准库。

## 要解决的问题

现有 conformance 证明没有直接 `json.loads`，但没有证明三处改动在真实调用链中拒绝非有限数字且不产生副作用。

## 前置依赖

- WO-001。

## 本工单分约束

- 先写测试；当前实现已满足时不得修改源码。
- 若定向测试暴露直接缺陷，只能在对应 ST 的单一边界模块内修复。
- 不改变公开请求形状、错误合同、数据库 schema 或 Provider 网络行为。

## 允许改动范围

- `src/prp_runtime/settings.py`
- `src/prp_runtime/providers/openai_compatible.py`
- `src/prp_runtime/storage/sqlite.py`
- `tests/unit/providers/test_base.py`
- `tests/unit/providers/test_openai_compatible.py`
- `tests/unit/storage/test_store.py`
- `ai/STATE.md`
- `ai/LATEST-REPORT.md`

## 禁止改动范围

- 其他源码/测试、依赖、配置、schema.sql、README、Git metadata。

## 改动坐标

- `Settings.from_env` / `_profile_from_json`。
- `OpenAICompatibleProvider.complete` / `_build_payload`。
- `SqliteStore.append_event` / `list_events`。

## 子任务顺序

1. WO-002-ST-001：Settings 环境 JSON 行为测试。
2. WO-002-ST-002：Provider schema 出站前拒绝测试。
3. WO-002-ST-003：事件账本写入拒绝与零落库测试。
4. WO-002-ST-004：三边界联合定向回归和静态检查。

## 完成定义

- NaN、Infinity、-Infinity 和溢出为 infinity 的数字在三个目标边界均不可通过。
- Provider 不发送 HTTP；SQLite 不新增事件行；合法输入行为保持。
- 联合定向 pytest、ruff、mypy 全部通过。

## 验收标准

- 测试调用实际 Settings/Provider/Store，不以源码扫描替代。
- 不使用 skip/xfail，不断言完整第三方错误文本。
- 无跨边界源码修改，无新增依赖或配置。

## 测试要求

- 每个 ST 只运行其列出的模块级测试和静态检查；不得全量。

## 资源策略

- 临时 SQLite、mock HTTP、无真实网络；串行，每条最多 240 秒。

## 风险

- Pydantic 可能包装 `StrictJsonError`；测试应断言拒绝和副作用，不绑定不稳定完整文案。
- Provider 直接构造请求可绕过上层 OutputRequirement，必须证明仍在 HTTP 前拒绝。

## 回滚点

- 三个边界分 ST；可分别回退当前边界测试/直接修复，不影响其他边界。

## 硬停止条件

- 需要改变公共 API/错误结构、schema、依赖或其他模块才能通过。
- 同一失败两次、两轮修复耗尽、测试触发真实网络或非临时数据库。
