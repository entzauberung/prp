# WO-003 最终 Diff 审计与人工 R2 门禁

## 工单目标

对比 WO-001 基线，输出最终 staged/unstaged/untracked 逐文件证据，并在人工批准后让全量门禁验证同一个最终工作树。

## 要解决的问题

旧门禁只记录 staged 数量，未证明覆盖后来新增的蓝图文件，也未记录 unstaged/untracked。最终交付必须消除快照歧义。

## 前置依赖

- WO-002。

## 本工单分约束

- 功能冻结；不修源码或测试。
- ST-001 是 R1 最终审计；ST-002 是唯一 R2 人工批准门禁。
- R2 失败不现场修复，不把旧批准沿用到新蓝图。

## 允许改动范围

- `ai/STATE.md`
- `ai/LATEST-REPORT.md`

## 禁止改动范围

- 全部源码、测试、依赖、配置、文档、Git metadata 和执行协议。

## 改动坐标

- 基线到最终的文件集合变化。
- staged/unstaged/untracked、双 whitespace check、定向回归和全量门禁。

## 子任务顺序

1. WO-003-ST-001：最终 Git 三视图、范围对比和定向交付审计。
2. WO-003-ST-002：人工批准后的全量 pytest/ruff/mypy 与最终 Diff 检查。

## 完成定义

- 最终文件表可由报告直接复审，且仅含基线与本蓝图允许变化。
- R2 获批并全部通过；最终报告分别写 staged、unstaged、untracked，不混成一个数字。
- R2 后只允许 STATE/REPORT 的协议更新，并在报告中明确标记。

## 验收标准

- 无未登记文件、无构建产物、双 Diff whitespace 通过。
- 定向交付测试通过且无 skip/xfail。
- 全量 pytest 0 failure、ruff 0 error、mypy 0 error。

## 测试要求

- ST-001 仅定向；ST-002 是唯一全量 R2。

## 资源策略

- 命令严格串行；R1 每条 300 秒，R2 每条 600 秒；无网络、无服务。

## 风险

- STATE/REPORT 在门禁后按协议更新，会形成预期控制面差异；不得误报为源码快照变化。
- staged 与工作树可能不同；全量测试验证工作树，报告必须同时保留 index 视图。

## 回滚点

- ST-001 不改项目；R2 前停在待批准。R2 失败后 BLOCKED，不回退用户文件。

## 硬停止条件

- 最终集合无法与基线对齐、发现第三类文件或任一 Diff check 失败。
- 未获 R2 批准、任一 R2 命令失败/超时或发生资源异常。
